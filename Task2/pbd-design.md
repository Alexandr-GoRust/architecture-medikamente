# Task 2. Целевая архитектура MVP с Privacy by Design (C4 контекст)

Диаграмма: `c4-context-tobe.drawio`. Новые блоки к проектируемым системам
(портал клиентов, портал ресепшена, платёжный шлюз, CRM, интеграция
с лабораторией) и где проходит каждый из 7 принципов PbD.

## Новые блоки архитектуры

| Блок | Роль (какой принцип PbD закрывает) |
|---|---|
| **Keycloak (IAM)** — OIDC/OAuth 2.0 + PKCE, MFA для сотрудников, RBAC/ABAC | Принцип 3 (встроено в дизайн): доступ «только лечащий врач», ресепшен не видит медданные; принцип 5: короткоживущие токены |
| **API-шлюз лаборатории/партнёров** — контракты скрывают PHI-категории, OAuth scopes, rate limiting | Принцип 2 (privacy by default): конфиденциальные категории закрыты в контракте по умолчанию — «новые интеграции не перевалидируются» (цель бизнеса №1); один пациент не видит другого |
| **Теги данных в CRM/ЭМК** (PII/PHI/Financial/HR) | Принцип 3: защита следует за данными (тег → шифрование/доступ/маскирование); база для CI-проверки релизов (финальное состояние To-Be) |
| **Аудит и алертинг** — журнал всех обращений к PHI/PII, правила нетипичных действий (UEBA), оповещения | Принцип 1 (проактивность) + 6 (прозрачность): расследуемость, алерт до разрастания инцидента; прямое требование To-Be |
| **Панель согласий в ЛК пациента** — что собираем, отзыв согласия, запрос на удаление | Принцип 7 (уважение к пользователю) + 152-ФЗ: «прекратить обработку по запросу» |
| **Аналитический слой (Data Lake + BI/ML)** — отдельный контур, только обезличенные данные | Принципы 2 и 4 (positive-sum): BI/ML/AI работают, а PHI не покидают операционный контур — псевдонимизация/агрегаты |

## MVP (промежуточное состояние) — что уже обеспечено

Запись пациента через портал/ЛК → ресепшен видит её в своём портале и напоминает
за день (пациенту — пуш, специалисту — уведомление). Категории данных пациентов
разнесены по доменам: расписание/записи (CRM), медданные (ЭМК), платежи
(шлюз/1С). Доступ — по ролям (RBAC: ресепшен/кассир/врач) и атрибутам
(ABAC: «лечащий врач», «свои документы по sub»).

## Финальное состояние (год) — расширения

Мобильное приложение + голосовой робот (подтверждение/отмена записи →
уведомление ресепшену); тегирование всех защищаемых данных; автоматическая
проверка релизов на работу с тегированными данными → отчёт в мониторинг;
аудит доступа и трекинг нетипичных действий с оповещениями.

## НФТ

- **Безопасность (конфиденциальность)**: шифрование at rest/in transit,
  своевременное удаление (сроки хранения), стоп-обработка по запросу;
- **Масштабируемость**: stateless-сервисы в Kubernetes (стек компании),
  Postgres/ClickHouse растут с филиалами;
- **Сопровождаемость**: домены с явными контрактами, каталог данных;
- **Конфигурируемость**: политики тегов/доступа — в конфигурации (Atlas/Keycloak),
  без доработок кода.
