# Архитектура «Медикаменте» — проектная работа спринта 10

Кейс: медицинская компания (РФ, 152-ФЗ), ручные процессы на Excel/сканах
и 1С → автоматизация под пятикратный рост с защитой конфиденциальных данных
(Privacy by Design, DFM, Data Minimization, шифрование) и планом миграции.

## Состав решения

| Задание | Артефакты | Суть |
|---|---|---|
| **Task1** Анализ As-Is | `problems.md`, `dfd-1-booking.drawio`, `dfd-2-medcard.drawio`, `dfd-3-payment.drawio`, `dfd-4-lab.drawio` (в каждом As-Is + To-Be) | 7 неучтённых массивов конфиденциальных данных, 12 проблемных зон, способы защиты по категориям (шифрование/обфускация/обезличивание), механизм тегирования; DFD по 4 процессам с мерами на каждом потоке |
| **Task2** To-Be (PbD) | `c4-context-tobe.drawio`, `pbd-design.md` | C4-контекст MVP: Keycloak (RBAC/ABAC, MFA), API-шлюз (контракты скрывают PHI), аудит+алертинг, теги данных, аналитический слой только на обезличенных данных; покрытие 7 принципов PbD |
| **Task3** Шифрование | `data-encryption-strategy.md` | Классификация 8 категорий данных (PII/PHI/Financial/HR) → обоснование → инструменты at rest / in transit / in use; автоматизированный контроль (DLP, аудит, UEBA); реестр ПО/аппаратных средств; 152-ФЗ/ФСТЭК №21 |
| **Task4** Узкие места | `ishikawa.drawio`, `migration-bottlenecks.md` | Исикава (6 категорий: инфраструктура/ПО/данные/интеграция/персонал/процессы) + 9 рекомендаций с приоритетами P0–P2 |
| **Task5** Cutover-план | `cutover-plan.md` | Выбор **Parallel Run** (обоснование против HLD и Branch by Abstraction), 7 этапов с ролями и сроками, триггеры и план отката, карта рисков |
| **Task6** Движок классификации | `c2-classification-engine.drawio`, `classification-engine.md` | C2: профилировщик + детектор (regex/ML) + очередь ревью + теги (Atlas) + policy engine; слои DWH raw→sensitive→curated→gold; метрики эффективности; масштабирование |

Диаграммы — draw.io (XML), источники генерации в `.sources/build_*.py`
(воспроизводимость).
