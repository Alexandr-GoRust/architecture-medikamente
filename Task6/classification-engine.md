# Task 6. Движок классификации данных перед загрузкой в хранилище

Диаграмма: `c2-classification-engine.drawio` (C2, контейнеры движка).

## 1. Движок классификации при пакетной загрузке (схемы меняются, разметки нет)

Конвейер: **Ingestion (NiFi/Kafka)** → **Профилировщик** (статистика колонок,
словари, обнаружение новых/изменившихся полей) → **Детектор классов**
(regex/словари: СНИЛС, паспорт, ФИО, диагнозы; ML-классификатор для текстов
и сканов) → **Тег-менеджер** (теги PII/PHI/Financial/HR в каталог Apache Atlas,
с lineage) → **Policy engine** (по тегу: маскирование / токенизация /
пропуск) → загрузка в слои DWH.

Ключевые решения:
- **Схема-agnostic**: приём в слабо-типизированном виде (JSON), профилировщик
  сравнивает с прошлым профилем — новые колонки автоматически попадают
  на классификацию (структурные изменения не «проскакивают» мимо разметки);
- **Два контура решения**: auto (высокая уверенность) и **очередь ревью**
  (низкоуверенные кейсы подтверждает владелец домена данных) — ML дообучается
  на ревью, точность растёт;
- Теги живут в **каталоге отдельно от схем** — переименование колонки
  не теряет класс конфиденциальности.

## 2. Слои в хранилище (конфиденциальные данные всё же попадают в DWH)

| Слой | Что содержит | Меры |
|---|---|---|
| **raw** | как пришло (для перепроигрывания) | шифрование, доступ только движку; минимальный срок жизни (TTL) |
| **sensitive** | всё, что признано PII/PHI/Financial | шифрование полей (AES-256), доступ по ABAC узкому кругу, аудит каждого чтения |
| **curated** | обезличенное: маскирование/токенизация идентификаторов, агрегаты | доступ аналитикам |
| **gold (витрины)** | готовые датасеты BI/ML | только k-анонимные/агрегированные данные |

Дополнительные меры: CI-проверка «в gold не попадает незамаскированное
конфиденциальное» (цель-метрика = 0); политики тегов в конфигурации Atlas
(конфигурируемость без доработок); lineage от источника до витрины —
можно доказать регулятору, откуда что в отчёте.

## 3. Метрики эффективности классификации и оптимизация

- **Покрытие**: % полей/таблиц с тегами (0 нетегированных конфиденциальных — цель);
- **Точность/полнота** (precision/recall) против ревью-выборки — полнота важнее:
  пропуск PII в curated дороже ложной тревоги;
- **Время от нового поля до тега** (SLA, например 1 день);
- **Доля ручного ревью** — снижение = рост качества ML;
- Использование: дрейф метрик → точка оптимизации (перекалибровка порогов,
  новые словари, дообучение); отчёты — в систему мониторинга/алертинга.

## 4. Scalability

- Детектор и policy — **stateless-воркеры**: горизонтальное масштабирование
  в Kubernetes (стек компании), батчи партиционируются по источникам;
- Очередь Kafka — буфер пиков (5-кратный рост объёмов данных кейса);
- Profiler/Atlas — фоновые задания по расписанию, не в критическом пути загрузки;
- Рост числа пользователей/аналитиков: доступ к curated/gold через BI-слой
  с кешированием витрин (ClickHouse), sensitive-слой не масштабируется наружу.
