# Task 1. Аудит безопасности данных «Медикаменте» (As-Is)

Анализ по подходам Privacy by Design (7 принципов), Data Flow Management
(DFD по каждому процессу — см. `dfd-*.drawio`) и Data Minimization.

## 1. Неучтённые конфиденциальные данные (находки инвентаризации)

По описанию компании данные «лежат в непосредственной близости к пользователям».
Вне внутренних систем и учёта находятся:

1. **Журнал записи на приёмы** (Excel у ресепшена) — Ф.И.О., телефон, причина
   визита, лечащий специалист: поведенческий профиль пациентов, нигде не учтён
   как реестр ПДн.
2. **Расширенные анкеты пациентов** (адрес прописки, место работы/учёбы,
   хронические заболевания) — бумага/сканы на общем диске: спец. категория ПДн
   (здоровье) в общем доступе файлового сервера.
3. **Медицинские карты и заключения** — Excel/JPG/PDF на общем диске без
   аудита доступа: любой сотрудник с доменной учёткой может открыть.
4. **Результаты анализов** — пересылаются по Outlook (внутри и наружу,
   включая лабораторию): копии ПДн в почтовом ящике вне каких-либо регламентов.
5. **Двойной учёт платежей** (кассиры: Excel + 1С) — копия платёжных данных
   в «боковом» Excel-файле, о котором знает только смена кассиров
   (типичные «коллективные знания»).
6. **Контракты клиентов** (заключает ресепшен) — сканы с паспортными данными
   на общем диске.
7. **Кадровые данные и зарплаты** — 1С:Бухгалтерия в файловом режиме: доступ
   к файлу БД = доступ ко всему, разграничения нет.

## 2. Список проблемных зон (аудит против практик защиты данных)

| # | Проблемная зона | Чем нарушает (принцип/требование) | Последствие |
|---|-----------------|-----------------------------------|-------------|
| П1 | Общий файловый диск без разграничения доступа к медкартам | Privacy by Default (защита по умолчанию), 152-ФЗ меры защиты | Любой сотрудник читает спец. категории ПДн; инсайдерская утечка |
| П2 | Отсутствие аудита действий с данными | Прозрачность и подотчётность (принцип 6 PbD), приказ ФСТЭК №21 | Утечку невозможно расследовать; нет ответственных следов |
| П3 | Excel/JPG/PDF как первичные хранилища | Конфиденциальность, заложенная в дизайн (принцип 3) | Нет шифрования полей, нет контроля версий, копии расходятся по почте |
| П4 | Пересылка медданных и анализов по Outlook | Защита в передаче (принцип 5), DFM: неконтролируемые потоки | Копии ПДн в почте, риск отправки не тому адресату, внешний ретранслятор |
| П5 | 1С в файловом режиме (Бухгалтерия, Торговля) | Управление доступом, шифрование at rest | «Всё или ничего» по файлу БД; платёжные и кадровые данные без гранулярных прав |
| П6 | Двойной учёт платежей (Excel + 1С) кассирами | Data Minimization, единый источник правды | Избыточные копии, расхождения, невозможность верификации |
| П7 | ККМ ↔ 1С через OLE/TCP без защиты канала | End-to-End безопасность (принцип 5) | Перехват платёжных данных в ЛВС |
| П8 | Сервер в том же здании, что офис; нет упоминаний бэкапа/DR | Доступность и восстановимость | Пожар/затопление/кража = потеря всех медкарт (RPO→∞) |
| П9 | Ручная обработка расширенных анкет | Минимизация данных (принцип 2) | Собираются данные, не нужные для записи (место работы/учёбы) |
| П10 | Только доменная аутентификация, нет ролей/атрибутов | Наименьшие привилегии | Кассир видит медкарты, врач — бухгалтерию |
| П11 | Нет управления согласиями и сроками хранения/удаления | 152-ФЗ (право на отзыв согласия, «забвение») | Невозможно выполнить требование клиента прекратить обработку |
| П12 | Нет тегирования/классификации данных | To-Be: пометки данных, проверка релизов | Защита «на глазок»; новые интеграции каждый раз ревалидируются вручную |

## 3. Данные для защиты и способы защиты (список)

| Данные (категория) | Где сейчас | Способ защиты: шифрование | обфускация | обезличивание |
|---|---|---|---|---|
| Диагнозы, анализы, заключения (PHI) | Сканы/Excel, общий диск | AES-256 at rest (диск+поля БД), TLS 1.3 | скремблирование в тестовых средах | псевдонимизация для BI/ML |
| Паспортные данные, СНИЛС | Сканы контрактов | Шифрование полей | токенизация номеров | маскирование в отчётах (****-1234) |
| Ф.И.О., телефон, e-mail, дата рождения | Excel-журналы, Outlook | Шифрование БД, TLS | — | агрегирование/псевдонимизация в аналитике |
| Платёжные данные и суммы | Excel кассиров, 1С, ККМ | Шифрование БД, TLS-канал ККМ | токенизация карт | — |
| Кадровые данные, зарплаты | 1С:Бух (файл.) | Шифрование тома/БД | — | маскирование в управленческих отчётах |
| Содержимое анкет (работа/учёба, адрес) | Бумага + сканы | Шифрование сканов | — | исключить сбор (Data Minimization) — данные не нужны для записи |

## 4. Механизм тегирования данных (предложение)

1. **Классификация при создании**: теги категорий в каталоге данных —
   `PII` (идентифицирующие), `PHI` (медицина), `Financial` (платежи),
   `HR` (кадры), `Public` (открытые). Теги ставятся: автоматически
   (дискавери-сканер по шаблонам: номера паспортов, СНИЛС, названия колонок
   ФИО/диагноз; ML-классификатор для сканов) и вручную владельцем домена.
2. **Политика тегов**: тег определяет поведение систем — `PHI` → шифрование
   полей + доступ «только лечащий врач» + полный аудит; `Financial` →
   токенизация + разделение полномочий; `PII` → минимизация и маскирование
   в не-прод средах.
3. **CI-контроль релизов** (требование To-Be): автоматическая проверка
   «релиз работает с тегированными данными корректно» → результат в систему
   мониторинга/алертинга.
4. Инструменты: Apache Atlas (open-source, в стеке есть Java-экспертиза) как
   каталог+теги+lineage; при росте — платформа класса BigID/OneTrust.

## 5. Список инструментов/методов для потоков из DFD

- TLS 1.3 на всех каналах (портал, API лаборатории, мобильное приложение);
- OAuth 2.0/OIDC (Keycloak) + RBAC/ABAC для доступов по ролям и атрибутам;
- Шифрование at rest (FDE/SED, шифрование БД, SSE объектного хранилища);
- Токенизация и динамическая маскировка ПДн в сервисах с широкой аудиторией;
- DLP на АРМ и почте; журнал аудита доступа + UEBA-алерты;
- Автоматические ночные сверки (этап Parallel Run миграции);
- Вывод ПДн из Outlook: интеграция с лабораторией только через API-шлюз.

Доработанные диаграммы потоков с мерами на каждом этапе — `dfd-*-tobe.drawio`.
