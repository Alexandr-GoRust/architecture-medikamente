# Task 3. Data Encryption at Rest and In Transit — стратегия защиты данных

Компания «Медикаменте», РФ. Ключевой закон — 152-ФЗ «О персональных данных»
(специальные категории ПДн — здоровье; требование локализации: хранение ПДн
граждан РФ на серверах в РФ). Дополнительно учитываем 325-ФЗ (криптосредства
должны быть сертифицированы ФСБ/ФСТЭК при защите ПДн в ИСПДн) и приказ
ФСТЭК № 21 (меры защиты в ИСПДн).

## 1. Классификация данных (что защищать и зачем)

| # | Данные | Где живут/двигаются (As-Is) | Класс чувствительности | В чём необходимость защиты | Инструменты защиты |
|---|--------|------------------------------|------------------------|----------------------------|--------------------|
| 1 | Медицинская карта: диагнозы, назначения, результаты анализов, заключения | Excel/сканы JPG-PDF на общем диске; пересылаются по почте Outlook | **Спец. категория ПДн (здоровье), PHI** | Требование 152-ФЗ (согласие + усиленная защита); репутационный и регуляторный риск утечки; основа доверия клиентов | At rest: AES-256 (диск/БД, шифрование полей), SED-диски. In transit: TLS 1.2+/1.3. В использовании: динамическая маскировка, RBAC/ABAC «только лечащий врач», аудит доступа |
| 2 | Паспортные данные, СНИЛС, адрес прописки | Бумага + сканы на общем диске, Excel-журналы | ПДн (идентифицирующие) | Прямая идентификация личности — приоритетная цель утечек; 152-ФЗ | Токенизация/обезличивание для аналитики; шифрование полей БД; маскирование в тестовых/демо-средах (статическое); доступ по принципу наименьших привилегий |
| 3 | Ф.И.О., дата рождения, телефон, e-mail | Excel-журналы ресепшена, Outlook | ПДн (базовые) | Массовая рассылка/спам при утечке; идентификация человека | TLS при передаче; шифрование БД; минимизация сбора (Data Minimization); обезличивание (псевдонимизация) в BI |
| 4 | Платёжные данные, чеки, суммы оплат | 1С:Бухгалтерия (файловая), Excel у кассиров, ККМ | Финансовые ПДн / PCI-подобные | Финансовое мошенничество; споры с клиентами; 152-ФЗ | Токенизация номеров карт; шифрование БД 1С (перевод из файлового режима); TLS между ККМ–1С–шлюз; разделение полномочий (кассир не видит медданные) |
| 5 | Кадровые данные сотрудников, зарплаты | 1С:Бухгалтерия (кадровый учёт) | ПДн сотрудников | Внутренние утечки и конфликты; 152-ФЗ | Шифрование БД; RBAC (кадровик/бухгалтер); аудит обращений; маскирование в отчётах для руководителей |
| 6 | Данные лаборатории (направления/результаты) | Excel, пересылка почтой | Спец. категория (здоровье) | То же, что п.1; внешний контур передачи | Интеграционный API-шлюз: TLS 1.3, OAuth 2.0scopes, контроль контрактов (скрытие конфиденциальных категорий), шифрование полей |
| 7 | Журнал записи на приём | Excel у ресепшена | ПДн + расписание (поведенческий профиль) | Слив расписания = профиль посещений клиники | Перенос из Excel в CRM (шифрованная БД); аудит; минимизация (не хранить причину визита в журнале) |
| 8 | Учёт ТМЦ и закупок | 1С:Торговля и склад (файловая) | Коммерческие данные (не ПДн) | Целостность и доступность; коммерческая тайна | Резервное копирование; разграничение доступа; интеграция с 1С:Бух по защищённому каналу |

Критерии классификации: (а) идентифицируемость (№37а-правило квизов: по данным
можно опознать человека?), (б) специальная категория (здоровье), (в) профиль
риска (массовость, внешний контур, финансовый ущерб), (г) состояние данных
(покой / передача / использование).

## 2. Базовые инструменты защиты (реализовать)

**At rest (покой):**
- Полное шифрование дисков (FDE) серверов и ноутбуков, SED-диски для новых АРМ;
- Шифрование БД (TDE или полевое AES-256): PostgreSQL (CRM/порталы) — pgcrypto/шифрование томов;
- Шифрование объектного хранилища сканов (S3 SSE);
- Управление ключами: выделенный KMS/HSM, ключи отдельно от данных, ротация.

**In transit (передача):**
- TLS 1.2+ (целевой 1.3) для всех веб-порталов, API и мобильного приложения;
- VPN/IPsec для каналов филиалы–офис и до лаборатории;
- Отказ от пересылки ПДн по Outlook (замена — защищённый обмен через API/шлюз);
- Отключение устаревших протоколов (SSL, старые TLS).

**In use (использование):**
- Динамическая маскировка ПДн для ролей без необходимости видеть целиком;
- Статическая маскировка/обфускация данных для тестовых и демо-сред;
- Токенизация идентификаторов в аналитическом контуре (BI/ML обучаются на обезличенных данных);
- Минимизация объёма данных, загружаемых в память приложений.

## 3. Автоматизированный контроль

- **Классификация/тегирование**: сканеры-дискавереры (BigID-класс / open-source аналоги) + теги PII/PHI/Financial в каталоге данных; CI-проверка релизов на работу с тегированными данными (требование финального состояния To-Be);
- **DLP** на рабочих станциях и почте: перехват попыток выгрузки ПДн в Excel/USB/личную почту;
- **Аудит доступа**: журналирование всех обращений к медкартам; UEBA-правила нетипичных действий (массовые выгрузки, доступ вне графика) → алерты (требование To-Be «оповещения при несанкционированном доступе»);
- **Секреты и ключи**: vault, автоматическая ротация, алерт на утечку ключей в git;
- **Мониторинг целостности** и регулярный контроль соответствия (аудит ИСПДн по приказу ФСТЭК №21).

## 4. Реестр программных и аппаратных средств защиты

| Тип | Средство | Назначение |
|------|----------|-----------|
| Шифрование томов/дисков | LUKS / BitLocker / SED | At rest на серверах и АРМ |
| Шифрование БД | PostgreSQL TDE/pgcrypto, шифрование томов | Полевое и томовое шифрование CRM/порталов |
| KMS | HashiCorp Vault / YubiHSM (или сертифицированный HSM) | Хранение и ротация ключей (отдельно от данных) |
| TLS/сертификаты | NGINX/HAProxy + Let's Encrypt/корпоративный CA | In transit (порталы, API) |
| VPN | WireGuard/IPsec-роутер | Каналы филиалы–офис, лаборатория |
| IAM/RBAC | Keycloak (из стека компании) + роли/атрибуты | Доступ «только лечащий врач», наименьшие привилегии |
| DLP | Symantec/McAfee DLP-класс или open-source (Osquery-контроль) | Контроль утечек на конечных точках |
| Классификация/каталог | Apache Atlas / BigID-класс | Теги PII/PHI, lineage, поиск неучтённых данных |
| Аудит/UEBA | Wazuh / Elastic Security + правила аномалий | Журнал доступа, алерты на нетипичные действия |
| Резервное копирование | Bacula/restic + шифрование бэкапов, копия в другом помещении | Доступность и RTO/RPO |

> Для соответствия 325-ФЗ при обработке спец. категорий ПДн криптосредства
> выбираются из реестра сертифицированных (ФСБ/ФСТЭК); конкретные продукты
> фиксируются на этапе закупки.
